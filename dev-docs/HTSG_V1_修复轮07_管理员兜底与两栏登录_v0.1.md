## 1. 问题与用户裁定

核实（读代码，未改源码）：

1. **会一直登录不了的情形：** 改账户时主库写不进（或启动时标记还在）且主库一直读不了；需要核对时 `.local` 写不进；账户文件坏了或丢了，同时主库读不了；主库和文件都没有账户。前三种由维护周期每 `stats_interval`（60秒）重试，条件恢复即恢复；但没有时间上限，条件不恢复就一直登录不了。手工办法只有删标记再重启，没有写进文档，且主库回来之前可能让刚停用的账户又能登录。
2. **忘口令没有办法：** 主库里已有管理员，`init-accounts` 不再建；页面上也没有（修复轮02 第4节）。
3. **接口只建只读用户靠的是“已有管理员”：** `POST /api/admin/accounts` 收到 `role=admin` 时，是因为账户表里已有管理员才被拒。
4. **凭据文件与登录框：** `initial-credentials.json` 是一行 `{"admin": "admin:<令牌>"}`；登录框只有一栏，要整串输入“用户名:令牌”。
5. **闲置字段：** `ui.history_windows`（60/300/900）只在配置校验里出现，页面不读；它原是旧页内历史图的窗口选项（终版第18.1节 `ui` 一行“旧页内历史设置随第14–17节改造”）。演练实例的配置 `.local/rehearsal/config.json` 里也写着它。

用户裁定（2026-10-28）：

- **兜底凭据：** 部署时生成的初始口令同时是兜底凭据，永久有效，页面上撤不掉；账户没核对上、管理员改过或忘了口令时都能用它以管理员登录。哈希另存在账户文件旁的兜底文件里，只在部署建管理员时写，运行中只读；读不了不阻止启动，只是没有兜底，日志提示。忘口令用它登录后再改，不另做本机重置命令。
- **登录：** 登录页分“用户名”“口令”两栏；凭据文件里用户名、口令各占一行；交接后由业主离线保管，不留在现场电脑上。
- **页面和接口只能建只读用户**（终版第2.3节）。
- **研究配置清理：** 删除 `ui.history_windows`；按修复轮05 的先例，配置仍写有时校验不通过并指明字段，不静默忽略；演练实例的配置一起删掉这一项。
- 以上已写入终版第2.3节和第18.1节（文档提交 `2da7b1d`）。

## 2. 改动

- **`htsg/auth.py`（候选摘要随之改变）：**
  - 兜底文件 `admin-fallback.json`（账户文件旁）只存初始口令的盐和 scrypt 哈希；`write_fallback` 先写临时文件并 fsync，再改名替换，只由部署调用。
  - `Accounts` 启动时读兜底文件：不存在就没有兜底；读不了（空、截断、全零、乱码、结构不对、读取出错）时不抛错，记下原因（`fallback_unreadable`），只是没有兜底。
  - `verify`：先按账户表核对（有未确认标记时跳过，同原来）；不通过且用户名是 `admin` 时再核对兜底哈希，通过即以管理员身份登录，不看账户状态。用兜底凭据登录时每个请求算两次 scrypt（账户表一次、兜底一次），约多34毫秒 CPU；没改过口令时账户表那次就通过，只算一次。
  - `create` 可带入口令（部署用），不带时照旧随机生成。
- **`htsg/cli.py`：** `init-accounts` 先生成初始口令，先写兜底文件和凭据文件（`{"username": "admin", "password": …}`，分行排版），再把管理员写进主库和账户文件：中途断了就没有管理员，重跑时重新生成，两份文件一起覆盖；已有管理员时什么都不写，初始口令和兜底文件保持交出时的样子。提示语改为“交给业主离线保管，初始口令永久作兜底”。
- **`htsg/runtime.py`：** 启动核对账户之前，兜底文件读不了时记一条 `fallback credential unreadable (原因)`，没有兜底文件时记一条 `no fallback credential beside the account file`；都不影响启动。
- **`htsg/web.py`：** `POST /api/admin/accounts` 只收 `role=viewer`，其余返回 409（原来靠“已有管理员”挡住；兜底登录时账户表可能是空的）。接口描述不变，`docs/openapi.json` 未重新导出。
- **`htsg/static/index.html`、`htsg/static/app.js`（页面摘要随之改变）：** 登录页分“用户名”“口令”两栏，页面拼成“用户名:口令”发给后端，后端鉴权方式不变；登录后清空口令栏。新建只读用户时分开显示用户名和口令。改口令后的提示改为“下次登录用新口令；部署时的初始口令仍可作兜底”。
- **`htsg/research_config.py`、`config/research-sim.json`：** 删除 `ui.history_windows` 及其校验；配置仍写有时按 `extra="forbid"` 校验不通过并指明 `ui.history_windows`（同修复轮05）。研究配置的配置摘要随之改变。
- **`.local/rehearsal/config.json`（演练实例的配置，不入库）：** 同样删掉这一项（用户同意）；原文件备份在本次会话的临时目录。
- **`scripts/deploy_databases.py`：** 文件头说明加上兜底文件；提示语同 `init-accounts`。
- **`scripts/measure.py`：** 浏览器登录改为分两栏填写。
- **`README.md`：** 账户一段补凭据文件分行、离线保管、两栏登录、兜底凭据；开发简化登录改为“用户名、口令都填 admin”。
- **对硬规则：** 只碰登录路径和部署建管理员这一步；兜底文件运行中只读，启动只多读一个文件，读不了不抛错；不改库结构；采集、归档与重启路径不变。
- **未改：** `scripts/research_lab.py` 的凭据文件仍是一行 `{"admin": "admin:…", "viewer": "viewer:…"}`（研究现场工具，登录时要自己分成两栏）；后端仍按“用户名:口令”鉴权；管理操作记录不区分兜底登录与普通管理员登录。
