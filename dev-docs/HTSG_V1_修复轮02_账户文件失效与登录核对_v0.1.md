## 1. 问题与用户裁定

账户存两份：主库的 `account` 表是权威副本，`.local/accounts.json` 是本机校验用的副本（只存哈希）。改账户的顺序是：先写 `.pending` 标记，再在主库同一事务里写账户和管理操作记录，最后改写本地文件、删掉标记；标记存在时一律拒绝登录。

核实（读代码，并在临时目录复现，未改源码）：

1. **文件坏了，后端起不来（审核第3条）：** 启动时直接解析文件、没有容错，空文件、截断或全零都抛 `JSONDecodeError`，后端退出。文件会坏的原因：每次启动都按主库副本重写一次，改账户时也写；写法是先写临时文件再改名替换，但没有 fsync，断电时改名可能已落盘而内容没有。
2. **文件不存在，后端起不来（审核第3条）：** 启动检查到没有账户，就以 "Run init-accounts first" 退出，即使主库里有账户。
3. **标记留下且主库没有账户，永远起不来（清单外）：** 首次运行时主库还没有账户，后端先写标记再写库；这中间断电或断库，之后每次启动都抛 `RuntimeError`。
4. **改账户写库失败，全员登录不了直到重启（清单外）：** 标记一直留着，所有人（包括管理员）登录不了，实时页被断开；只有重启时和主库核对才恢复，而后端没有退出，守护脚本不会重启它。同类：启动时标记还在而主库读不了，后端不启动。

在守护脚本下，第1–3项都表现为后端反复启动又退出、一直不采集。

用户裁定（2026-10-26）：

- 第3条与上面第3、4项一起修，规则是：**账户问题一律不阻止启动和采集；没和主库核对上就拒绝登录，由维护周期自动重试核对。** 不采用“写库失败即退出、由守护脚本重启”的修法。
- 标记留下而主库没有账户时，用本机账户文件引导空库，不再抛 `RuntimeError`。
- 主库和文件都没有账户时照常采集，日志提示（去掉 "Run init-accounts first" 拦截）。

### 唯一管理员（用户 2026-10-26 提出并裁定）

- **目的：** 在流程上避免初始化阶段没有账户。旧流程里部署脚本不建账户，要另跑 `init-accounts`（建一个管理员和一个只读用户，只写账户文件）；漏了这一步就没有账户。
- **用户问：** 在前端登录页提示首次创建管理员，是否与这个目的矛盾。判断：纯前端首次创建与目的矛盾——后端启动到有人创建之间就是没有管理员的空窗；这段时间谁先打开登录页谁成管理员；主库和文件同时丢账户后空窗会再次出现；主库暂时读不了时，后端分不清“没有管理员”和“读不到”。拆成两步就不矛盾：部署时建好管理员，业主在页面上改口令。
- **裁定：** 部署时建好唯一管理员，写进主库和账户文件；页面和接口只能建只读用户；管理员可在页面上随时改自己的口令，不强制、不动库结构（强制首次修改要给账户表加标记，库结构须升代、已有库须重建，未采用）。管理员和只读用户一样存在主库和账户文件里，不写进现场配置（页面上改的口令在运行中写不进配置）。

## 2. 改动

- **`htsg/auth.py`（候选摘要随之改变）：**
  - 账户文件读不了（空、截断、全零、乱码，或读取出错）时不再抛错：当作没有本机副本，谁也不能凭它登录，记下原因，读到主库副本后重写。
  - 写标记和写账户文件都先 fsync 再继续：标记在请求主库之前落盘，新文件在替换旧文件之前落盘。
  - 主库没有账户时一律用本机文件引导，标记在也一样（不再抛 `RuntimeError`）；那次没写进主库的改动就此作废。
  - 只能有一个管理员：已有管理员时再建管理员被拒。
  - 新增改口令：账户改用自己的口令，旧凭据立即失效；口令至少8位、首尾不能有空格，连同“用户名:”不超过登录框的256字符。
- **`htsg/runtime.py`：** 启动时与主库核对账户，失败（主库读不了、文件写不进）不再让启动失败：标记在时为 `RECONCILIATION_REQUIRED`，拒绝所有登录；否则为 `LOCAL_VERIFICATION_CACHE_ONLY`，按本机副本校验。没核对上、或之后有改动未确认时，维护周期重试核对，最多每 `stats_interval`（默认60秒）一次，在归档写入线程上执行（与启动核对、数据库统计相同）。日志记：文件读不了；核对失败（状态变化时一次）；核对恢复；主库和文件都没有账户（提示运行 `init-accounts` 后重启）。
- **`htsg/cli.py`：** 去掉 "Run init-accounts first" 拦截。`init-accounts` 改为只建唯一管理员，同时写进主库（附管理操作记录 `CREATE_ACCOUNT`）和账户文件，凭据写进账户文件旁的 `initial-credentials.json`；主库或文件里已有管理员时不建；主库用不了时报错退出（部署时由人执行）。
- **`htsg/web.py`：** 新接口 `POST /api/admin/password`：仅管理员，改自己的口令，记 `SET_PASSWORD`；口令不合要求返回 422。
- **`htsg/static/app.js`（页面摘要随之改变）：** “系统管理·权限”页的建账户表单只建只读用户；新增“修改我的口令”表单（两次输入须一致；改后本页改用新凭据继续，不用重新登录）；权限表相应改写。
- **`scripts/deploy_databases.py`：** `install` 写完连接文件后建唯一管理员（主库，以及连接文件旁的 `accounts.json`），凭据写进 `initial-credentials.json`、不打印；已有管理员时不动。
- **`README.md`：** “运行管理”补一段账户行为；接口表、写入口说明、初始化步骤注释随之更新。
- **`docs/openapi.json`：** 用 `scripts/export_openapi.py` 重新导出，只多出改口令接口。
- **未改：** 终版设计；`scripts/research_lab.py` 在 new-lab 前遇到标记仍拒绝（研究现场工具，偏保守，不影响现场）。
