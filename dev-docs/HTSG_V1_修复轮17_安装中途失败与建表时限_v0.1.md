## 1. 现象与原因（用户报告，代码核实）

1. **建表被 3 秒上限取消**：安装程序给正常库建表时，每条语句用的是后端运行时的上限（`timing.db_statement_timeout`，默认 3 秒）。`install` 建 `ArchiveStore` 时根本没有传配置里的时限，所以改配置文件也调不了；建管理员账户（`init_accounts`）用的也是运行时的 3 秒。磁盘慢时（新库第一次写入要清零 16 MB 的日志文件，exFAT 上的虚拟盘扩容还要再清零，全都经过 USB）一条建表语句就会超过 3 秒，被数据库取消（数据库日志 18:57:12）。
2. **停下后续装不下去**：口令在开头随机生成、正常库已用它建好，但连接文件（存口令）要等两个库都建完才写。中途失败，口令就丢了；再双击时部署检查看到实例已在、连接文件不在，停在“先把它恢复回来”——可那个文件从没写出过。手册“中途出错再双击会接着做”在这一步不成立。

## 2. 改法

- 口令先落盘：生成口令后、建第一个实例之前，就把连接文件原子写出。中途失败后再运行，读到同一个口令，打开已建好的实例接着做。
- 安装有自己的时限：建表与建管理员账户用安装专用的时限——语句 600 秒、等锁 60 秒（`INSTALL_STATEMENT_SECONDS`、`INSTALL_LOCK_SECONDS`）。安装只做一次、此时没有别的程序用这两个库，放宽不影响运行时的稳定；运行时仍是 3 秒，可在配置的 `timing` 里调。
- 《模拟手册》第4.1节：虚拟盘文件放本机 NTFS 硬盘，不放 exFAT 的 USB 移动盘。

## 3. 测试

- 新用例（真实实例）：第一次运行在应急库建表时模拟“语句超时被取消” → 连接文件与口令已在盘上、正常库实例在、部署检查无问题；第二次运行完成，口令不变，管理员已建；四次建表都用安装时限（≥ 300 秒）。旧代码下这条用例过不了（连接文件不存在、时限为 3 秒）。
- `tests/test_deploy_databases.py` 19 项通过。

## 4. 那台机器怎么恢复

rc6 留下的是一个口令已丢的正常库实例。双击 rc6（或新版）模拟包的“3-清除模拟安装”即可去掉它（实例目录里只有本程序的 `pgdata` 和启动日志，清除工具认得），再用新版安装。
