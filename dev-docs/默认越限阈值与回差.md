# 默认越限阈值与回差（故障记录用）

版本：2026-10-09。依据用户授权（"越限回差阈值需要单独设定，目前先由你根据实际工程量拟定"），由 AI 按实际工程量拟定，作为[终版设计](HTSG_V1_终版设计_v1.0.md)的默认值；判定规则以终版设计第8节为准。

## 0. 定位

| 项目 | 内容 |
| --- | --- |
| 用途 | 只用于"有效值持续越限满 5 秒 → 形成故障记录"，故障记录是历史重现的参考点 |
| 与极值的关系 | 独立的另一套界限。[默认极值阈值](默认极值阈值.md) 标记坏数据并阻断计算；本表判定工艺越限。两者互不替代，不合并为一套 |
| 性质 | 科研监测默认值，不是保护定值、联锁定值或设备量程；部署时按现场资料修订配置后重启生效，不提供在线调参 |
| 不做的事 | 不按负荷自适应、不做多级报警、不做跳变或死点判断 |

## 1. 依据与取值原则

**依据来源：**
1. 电厂参数表 `../660MW锅炉主要设备及重要参数.xlsx`：
   - 主蒸汽压力 28～29.4 MPa；
   - 主蒸汽温度 600～620 ℃；
   - 再热蒸汽温度 620～623 ℃；
   - 给水温度 293～310 ℃；
   - 炉膛负压 −50～−100 Pa。
2. 参考前端 `htsg_hmi.html`（权威文件规定工程量暂以参考前端为准）：
   - 集箱金属温度 > 490 ℃ 预警（第 1283 行，材料 12Cr1MoVG）；
   - 内外壁温差 > 40 ℃ 预警、> 55 ℃ 报警（第 624–625、1187、1255 行）；
   - 应变表按占许用应力 140% 报红（第 1201、1243 行），其中高温许用应力 84 MPa（第 215 行）、高温弹性模量 170 GPa（第 211 行）；
   - 工质温度 = 435 − (1 − 负荷率)×18，金属温度 = 工质温度 + 30（第 431、566 行）；
   - 水冷壁工质流量低于额定 50% 时换热恶化（第 427–429 行）。
3. 模拟基线及场景：`config/research-sim.json`。

**取值原则：**
- **参考前端有定义的**，取其最高一级提示：有红色报警取红色；只有黄色预警的取黄色。
- **参考前端没有定义的**，取电厂参数表正常范围外加余量，并低于材料或保护量级。
- **只设有工艺含义的一侧**。滑压运行、低负荷下自然偏低的量（负荷、主汽压力、再热温度等）不设下限，避免把正常调峰记成故障。
- **回差**：取值来源为 10% × |阈值 − 正常读数 N|，按仪表常用分辨率取整；默认值以下表为准。高侧与低侧回差分别设定（`hysteresis_high`、`hysteresis_low`），不能用单个数值覆盖。

## 3. 判定规则

1. **严格判据**：x > high 或 x < low 才算越限；等于阈值不算。与极值规则口径一致。
2. **只用有效值**：参与判定的必须是质量 GOOD、非极值、所属源未断连且不在"通信数据待同步"状态的值；派生量须为 OK。
   - 无效、极值或断连会打断计时，不计作越限。
   - 极值属于坏数据，不形成工艺故障记录。
3. **确认**：同一方向持续越限累计满 5 秒（单调时钟）时，形成一条故障记录，内容包括：
   - 确认时刻，以及判定依据值、该值的原观测时间与版本，分别保存；不把依据值伪造成“第5秒的新样本”；
   - 通道、方向；
   - 当时生效的阈值与回差快照。
   - 只在值变化时上报的 OPC UA 测点不会产生新样本，计时须由每秒一次的定时检查，按当前有效值推进。
4. **待确认期间**：任一有效值回到阈值以内即重新计时，不需要越过回差。
5. **复归**：故障记录形成后，只有有效值满足 `value ≤ high − hysteresis_high`（高侧）或 `value ≥ low + hysteresis_low`（低侧）才复归，复归后可再次记录。
   - 值落在阈值与回差之间时保持已记录状态，不产生新记录。
   - 无效、断连不触发复归。
6. **上下限独立**：方向切换时重新计时。进程重启后计时清零；持续越限的情况在重启后可能再次形成记录，已有记录保留。

派生故障的批内多版本处理按终版第8.2节执行：受影响源输入同批出现不同值或质量版本时取消待确认计时，按有效批末结果重新开始；该取消不自行复归已确认故障。

## 4. 留存路径

| 层级 | 位置 | 状态 |
| --- | --- | --- |
| 定义与依据 | 本文件 `dev-docs/默认越限阈值与回差.md` | 已建立 |
| 运行配置 | `config/research-sim.json`：`points[].low`、`points[].high`、`points[].hysteresis_low`、`points[].hysteresis_high`；96路温差和8路换算应变使用 `derived[].low`、`derived[].high`、`derived[].hysteresis_low`、`derived[].hysteresis_high` | **待实施时写入**，原因见下 |
| 运行审计 | 数据库 `config_snapshot.payload`：每个 config_id 的完整配置（含阈值）随启动写入（`htsg/storage.py:113`） | 机制已存在 |
| 单条故障记录 | 数据库 `fault_point.payload.rule`：触发时的测点定义快照（`htsg/engine.py:218`） | 机制已存在；派生量故障须同样写入快照 |

**未在本次写入配置的原因：** 当前配置模型禁止未知字段，`hysteresis_low/hysteresis_high` 和派生量的 `low/high` 尚不存在。且 `Engine.assess()` 在配置了极值界限时会用极值代替越限阈值（`htsg/engine.py:105-115`）。只写一半会造成配置与行为不一致。实施时须一次完成以下改动：
- 增加上述字段；
- `assess()` 改用越限阈值，极值只作坏数据标记；
- 故障判定扩展到96路温差和8路换算应变；
- 计时改为按 1 秒节拍推进，通信有效时数值不变的越限也继续计时（现行 `faults.py` 在样本间隔超过 1.5 秒时会打断计时，与只在变化时上报的订阅冲突）；
- 复归边界改用 `≤` / `≥`，高侧、低侧分别使用 `hysteresis_high`、`hysteresis_low`；
- 故障记录分别保存确认时刻、依据值的原观测时间与版本。

## 5. 模拟场景预期

本节对应现有模拟场景，随模拟部分重新规划而更新，不属于后端架构设计。

| 场景 | 预期 |
| --- | --- |
| baseline | 无故障记录：壁温 ≤ 486.3 ℃，温差 20～23 ℃，应变 118～174 με，过程量均在阈值内 |
| load_cycle | 无故障记录：负荷最低约 480 MW，水冷壁流量最低约 1535 t/h，温差 15～18 ℃ |
| thermal_step（30 秒） | 2 条记录：temp_inner_01（542 ℃ > 490）与 delta_t_01（80 ℃ > 55）。strain_01 约 338 με，不越限。结束后壁温回落到 462 ℃（≤ 487），两条均复归 |
| extreme_temperature | temp_inner_01 达 962 ℃，被标为极值，**不形成故障记录**；delta_t_01 因极值输入不可用，同样不形成记录 |
| bad_quality / freeze（模拟信号断联）/ disconnect_* | 无故障记录；计时被打断或不推进 |

## 6. 边界

- 金属壁温 490 ℃ 与模拟基线最高 486.3 ℃ 仅相距约 3.7 ℃。这是沿用参考前端预警值的结果，模拟中不会误触发；现场若常态壁温更高，应按实际修订。
- 应变阈值基于 GF=6 与无温度补偿的暂定换算，只作科研默认值。
- 本文件给出的是默认值与判定规则，尚未在代码或配置中实施，也未经测试验证。
