## 1. 用户裁定（2026-10-30）

- 写死的能力边界（点数上限、灵敏系数6、采集时序、历史回看上限、只监听本机）都已确认，不改；NodeId 不检查格式要修。
- 修：Modbus 不完整应答导致进程退出、Modbus 采集无兜底、OPC UA 删订阅超时跳过断开，以及 NodeId 校验。
- 瘦身：每次请求都做 scrypt 改为记住已验证的凭据；账户以本机文件为唯一依据，**管理操作记录写不进就拒绝账户变动**。
- OPC UA 改为单点降级；被拒的点**等下次建订阅（重建或重启）时再试**（方案 A），运行中不另行补建。
- 滚动删除不动。

## 2. 改动

- **Modbus 不完整应答（`htsg/modbus.py`、`htsg/owner.py`）：** 设备返回的寄存器少于请求数时，这一请求按“设备已应答、数据不可用”处理（与协议异常同类，不算超时、不触发重连），本请求的点本轮记为未应答，通信日志原因码 `INCOMPLETE_RESPONSE`、详情写明应答与请求的寄存器数。解码函数遇到长度不符只判坏值，不再抛异常。此前 `struct.error` 会结束采集任务，进程退出后被看守程序拉起，再遇同样应答即反复重启。
- **Modbus 采集兜底（`htsg/modbus.py`）：** 未预料的异常记日志后断开、上报源断开、退避重连；发生在建连阶段的计入建连失败（原因码 `ERROR:<类型>`）。与 OPC UA 采集的已有做法一致。
- **OPC UA 拆除（`htsg/ua.py`）：** 删订阅超时不再跳过断开连接与取消发布任务；此前半开链路上每次重建都留下一个套接字和发布任务。
- **NodeId 校验（`htsg/config.py`）：** OPC UA 点的 `node_id` 按客户端库的解析规则校验，首尾有空白或标识为空也不通过；`htsg check` 与启动时都会报出点名。禁用的源同样校验。
- **鉴权缓存（`htsg/auth.py`）：** 每个请求仍鉴权；凭据第一次通过 scrypt 后，以本进程随机密钥的 HMAC 摘要记在内存，最多64条，满即清空；任何账户变动都清空；校验开始后发生了变动的结果不记；失败的不记。
- **账户以本机文件为唯一依据（`htsg/auth.py`、`htsg/runtime.py`、`htsg/archive.py`、`htsg/cli.py`、`htsg/web.py`）：** 删去主库账户副本的读写、未确认标记、启动核对与维护周期重试，以及“核对不上除兜底外谁都不能登录”的状态。变动顺序：新文件写好并落盘 → 管理操作记录写入主库 → 新文件替换旧文件；记录写不进时删除新文件、变动不生效、接口返回503。账户文件读不了时只有兜底凭据能登录，管理员在页面改口令即重建自己的账户。`init-accounts` 只看账户文件和兜底文件：已有管理员或已有兜底文件时不再新建（新建会让业主手里的初始口令失效）；凭据文件先于兜底文件、兜底文件先于账户写盘。主库 `account` 表保留不用，不升结构代次。自检的 `runtime.accounts` 取值改为 `FILE` / `FILE_UNREADABLE` / `NO_ACCOUNTS`。
- **OPC UA 单点降级（`htsg/ua.py`、`htsg/owner.py`、`htsg/ingress.py`、`htsg/records.py`、前端标签）：**
  - 建订阅时部分监控项被拒：订阅照常，被拒点原因为 `ITEM_REFUSED`，依赖它的派生量按既有规则为“输入不可用”，其他点与派生量不受影响；该代次记一条 `ITEMS_REFUSED` 状态（入历史）和一条通信日志；协商参数只统计被接受的监控项，另列被拒清单。全部被拒仍按建订阅失败、退避重试。
  - 监控项队列溢出：不再重建订阅；该批另记一条 `ITEM_OVERFLOW` 状态（点名单），观测本身保留带溢出位的状态码；该点及由它派生的结果的越限计时从这一批重新开始（同第8.2节批内多版本的处理）；自检计数 `item_overflows`。
  - 时效不变：订阅模式下不变的值不重发，单点无法自行判断是否过期，仍按源判定（3秒失效、6秒失步）。缺号仍整源重建。

- **点表工具（`tools/pointsheet/`，用户2026-10-30要求）：** Excel 点表与部署配置互转。内部编号固定，现场地址留空即不接入（OPC UA 只接一部分、其余作余量是正常用法）；依赖未接入点的派生量、界面测站、模拟信号自动去掉并列出；接入行有错按“表名 第几行 哪一列”报错且不生成文件；最后按后端配置规则整份校验。依赖 openpyxl 只供工具使用。用工具生成的 40 个 OPC UA 点加 7 路应变的配置起了模拟现场与后端，七个页面逐页打开，均正常、控制台无报错，历史查询有记录。
- **随之修改的前端文字：** 应变场页“8 个固定测点”改为按测站数显示；自检页“溢出按失步处理”改为“只影响该点，不重建订阅”。`scripts/research_lab.py` 去掉检查已不存在的账户未决标记的两行，模拟现场使用说明随之删去该句。

- **发布包（用户2026-10-30要求）：** `tools/release/build_release.py` 从已提交的版本（`git archive`）构建现场发布包，白名单只含程序 wheel、只含运行依赖的离线依赖包（`requirements.runtime.lock`，32 个，版本与 `requirements.lock` 一致）、部署与看守脚本、点表工具、`config/production.base.json` 与空模板、安装与运维说明、`verify.ps1` 与 SHA-256 清单、PostgreSQL 安装包；`--working-tree` 构建标明 SNAPSHOT 的未提交快照，只供演练。`config/production.base.json`：生产模式、与模拟配置相同的派生量、测站与模型、地址留空、数据源默认不启用，由测试保证与模拟配置同步。版本号升为 0.3.0。在临时目录按说明离线试装：依赖完整、点表生成配置并通过校验、部署计划通过、后端从包内启动后页面与静态文件正常。`deploy_databases.py` 开头说明改为管理员只写进账户文件、记录写主库。

## 5. 接受的限制

- 账户变动在记录已写入、新文件替换旧文件失败时（同目录改名失败，极少见），记录上有这次变动而文件没变；接口返回错误，管理员可重做。
- 被拒的监控项在服务器恢复该位号后，要等下次建订阅才采回来（方案 A）；通信·日志页列出被拒的点。
