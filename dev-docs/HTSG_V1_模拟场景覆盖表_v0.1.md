**场景是单一互斥状态：** 研究模拟器同一时刻只有一个场景（`POST /scenario`，下一次生成才生效），组合场景（如断连叠加越限）产生不了。**网页没有场景切换入口**，只有模拟控制端口的 HTTP 接口。

**结论（只列事实）：**
- 研究模拟器能产生的终版场景只有：明确断连（两种协议）、坏质量、满量稳定负载与初值突发；quiet 配置另可产生整源静止。
- 第 1、2、3、5、6、8、9、10 行在模拟层**没有覆盖**；其中 1、2、3、6、11 在真实协议服务器夹具上有覆盖，5、8、9 只有单元层。
- 在这张表有人逐行认领之前，不得写“完整模拟场景已验收”；D46／D47／D48 的证据也只对旧候选成立，G3 刷新后才对新候选成立。

## 追加：正式模拟前的处理选择与验收口径（供审核）

日期：2026-10-20。

**状态与效力：** 本节记录本轮讨论形成的逐行处理建议、页面验收口径及通信断联判据，供审核；不表示已修改模拟器、后端或页面，也不表示相应用例已通过。上方覆盖表保留追加前的现状记录。本节中用户已明确确认的范围是：**本期只判断后端与设备／网关之间的通信断联**；不增加逐点采样心跳、传感器断线诊断或按数值不变时长判故障。其余实施选择与验收门槛均为待审核建议。

上表第14行“冻结（信号断联）”“新判据未定”的表述由本次范围决定取代：后续应按“值及源时间戳保持时不误判断联”验收，不能把 `freeze` 等同于通信断联。第13行坏质量仍按测点不可用处理，不等同于通信断联。

### 1. 逐行处理选择

建议由研究模拟器承担常用运行场景，由真实协议测试夹具补齐协议异常，由确定性测试验证内部时序。每行都要有对应证据，但不要求所有异常都增加到研究模拟器的控制接口。

| 对应行 | 建议采用的处理 | 页面可见行为与验收要点 |
| --- | --- | --- |
| 1 单次超时 | 使用真实 Modbus 夹具，补后端＋页面＋归档闭环 | 受影响点及依赖派生量失效，业务页显示“—”及本轮超时原因；连接代次不变，不立即产生通信告警。恢复首轮应变变化量仅建基线，下一连续有效轮恢复求差；历史在失败轮终止旧值保持。 |
| 2 连续超时重连 | 使用真实 Modbus 夹具完成闭环 | 连续三轮整轮无有效协议响应后重连，页面显示重新同步；新代次有效输入到达后恢复相应值。三轮重连与10秒通信告警分别核对，不能将二者当成同一事件。多请求场景下库先主动关闭连接时，保留实际 CONNECTION 原因。 |
| 3 协议异常、部分成功 | 使用多从站夹具完成闭环，不改默认满量点表 | 未应答点失效，成功点继续更新；协议异常显示实际原因码和失败请求范围，不冒充网络断联。部分请求成功不使其他失败请求对应的输入恢复有效。 |
| 4 明确断连与恢复 | 纳入正式研究模拟，刷新候选证据 | 分别停对应服务器，该源相关值失效、趋势断线，另一源继续工作。收到有效响应后显示通信恢复；相关点取得有效初值后恢复计算；历史不跨中断连线。 |
| 5 调度跳拍 | 保留确定性调度测试，补一次页面状态核对 | 跳拍后的首次应变变化量不可用，下一连续有效轮恢复；不突然补出一串积压数据。计划轮次确实跳过、没有补发，须由测试记录证明，不能仅凭页面观察。 |
| 6 保持连接但停止发布 | 使用 PausableProxy 专项闭环 | 3秒数据失效；3–6秒内恢复且序号连续、无Overflow时保持同代次，历史另开有效段；达到6秒静默时告警并重建。不能用停止服务器代替保持连接的沉默场景。 |
| 7 静止、纯保活、稀疏变化 | 使用独立静止／稀疏模拟配置及驱动脚本 | 静止运行至少10分钟不误判失效；值保持，最后有效通信继续推进，原观测时刻不冒充页面刷新时刻。OPC UA静止值不逐秒重复归档；Modbus仍按计划轮读取。稀疏变化按正常发布周期送达。 |
| 8 静止越限确认 | 增加恒定越限模拟用例，使用配置或驱动脚本 | 选定点保持Good、源通信连续、数值越普通阈值且未越极值边界：先显示待确认，持续满5秒后显示已确认；即使没有新值通知也须确认。持续同一越限不重复生成故障，回到回差边界后复归。 |
| 9 缺号、Overflow、同批多版本 | 保留协议回调边界注入，补 Owner＋页面＋归档集成 | 缺号／Overflow进入重新同步、相关数据不可用，历史有效区间中断。同批短暂正常值取消对应待确认计时；派生量按终版批内多版本规则处理。页面无需闪现所有中间值，但测试须证明计时重置且无提前确认。此项不得标作真实线上异常注入已验证。 |
| 10 服务端修订参数 | 使用可定向修订参数的测试服务器专项验证 | 自检页同时显示请求值和实际值；队列修订为1时标注“覆盖不可检测”并继续运行；不满足时限约束时明确提示，不能静默显示兼容。已有正常协商测试不能代替主动修订参数场景。 |
| 11 连续失步退避 | 使用真实协议夹具反复制造五次实际失步 | 实际五次进入RESYNC后显示持续失步，连接失败次数另列。长期离线期间的重试失败不伪增失步次数；稳定有效通信60秒后清零。退避间隔由时序记录核对，不从日志条数推算。 |
| 12 库内后台任务停用 | 采用现有真实协议专项测试作为验收路径，不增加研究场景 | 页面持续收数仅是旁证；无库内周期Read、无自主recreate、正常Publish与安全通道续期继续工作，须由测试监测证明，不能仅凭页面判断。 |
| 13 坏质量 | 纳入正式研究模拟，核实上表“未核对”格并补证据 | 通信页显示实际质量、完整状态码和协议实际提供的原始载荷；协议无值时保持缺失。业务展示及依赖计算不可用，有有效协议响应时不报通信断联；历史保留无效区间，质量恢复后重新有效。 |
| 14 冻结 | 将 freeze 作为“值及源时间戳保持时不误判断联”的反例 | 冻结20秒但通信持续时，不产生通信断联；正常恒定值保持正常，恒定越限仍按5秒确认。不得将该场景签为传感器断线检测。 |
| 15 满量联调 | 纳入正式研究模拟与G3 | 208输入、209派生按各自有效性显示，七页切换正常；初值突发和稳定运行的归档可追平，断连恢复后历史可查询。队列峰值、延迟、维护耗时及恢复时间由测量报告核对，页面不卡顿本身不足以通过。 |

### 2. 页面验收与证据口径

- **总览／应变／热应力页：** 有效值、无效原因、越限待确认和已确认状态应一致；无效不补零，趋势不跨无效区间连线；未受影响的通道继续运行。业务页隐藏不可用数值，与通信页保留带质量标注的原始载荷是不同展示职责。
- **通信·日志页：** 每行的值、质量、观测身份及时间来自同一观测；区分明确断开、重新同步、通信恢复和告警解除。此页每5秒轮询，短暂状态可能错过，须结合当前运行日志和实时页录像核对，不能要求轮询恰好显示每一个中间状态。
- **历史页与CSV：** 可核对实收值、失效记录、有效段及保持边界；有归档丢失时显示归档缺口，显示与CSV一致。通信中断以相应失效／有效段边界表达，不必等同于归档写入丢失。达到行数上限也不能把最后显示值延长到已知下一次变化之后。
- **计时：** 5秒故障确认、3／6／10秒通信规则均按单调时间判定。Owner的周期检查在阈值到达后的下一次节拍处理，页面又有消息传输与刷新延迟；分别记录触发、后端判定、页面显示的时刻，不要求截图恰在第5.000秒变色，也不通过放宽判定阈值吸收调度延迟。
- **注入起点：** 从模拟服务器实际停止响应、协议质量实际改变等事件开始计时；`POST /scenario`返回仅说明控制请求已接受，不证明下一次生成和服务器重配已经发生。
- **恢复：** 连接建立、首次有效响应、点值恢复有效、归档追平分别记录；不把连接建立直接写成全部数据恢复，也不把`measure.outage.noticed_after_seconds`当作通信告警时延。

**本机性能门槛建议（待审核）：** 沿用[现有测量测试](../tests/test_measure.py)对应的口径：初值突发阶段全部417量有效后归档追平小于10秒；稳态测量结束后追平小于5秒；维护调用最大耗时小于2秒；接收到浏览器绘制的最大延迟小于2秒。合并等待中位数不超过140毫秒、最大值小于1秒，同时报告端到端p50／p95／p99及最大值；100毫秒配置值不写成硬实时保证。这些是本机模拟门槛，不能直接作为现场性能承诺。正式测量须覆盖实际重型统计维护周期，并列明是否另做阻塞注入，不能由缩短统计周期的短测试代替全部维护证据。

**逐行证据：** 保存候选提交、代码／配置摘要、运行命令、涉及通道、注入实际生效时刻、预期与实际状态、页面证据、后端／归档核对结果及恢复结果。对无直接页面证据的内部行为，写明采用的自动化断言。完成本节的选择不代表执行完成；只有对应证据齐备，才可将该行签为通过。

### 3. 通信断联判据

**用户已确认的范围：** 本期只判断后端与设备／网关之间的通信断联。值不变、源时间戳不变均不单独构成断联，不增加逐点采样心跳或传感器断线诊断。测点坏质量继续按现有质量语义处理，不推断其物理故障原因。

下列判据沿用[终版第11节](HTSG_V1_终版设计_v1.0.md#timing-contract)的3／6／10秒默认值，补明模拟验收与展示口径：

| 情况 | 判据与动作 |
| --- | --- |
| 已建立的连接被明确关闭／重置，或应用取得明确断开证据 | 发现后立即使受影响状态不可用并进入恢复流程；不等待静默阈值。持续通信告警仍按对应6秒／10秒规则独立推进。 |
| OPC UA无有效发布响应 | 当前订阅等待发布起点已建立后，按该订阅的有效通信证据检查：满3秒判数据失效但不因此重建；满6秒静默触发重建。源级满6秒无有效通信产生告警，基准按首次启用／最后有效通信计算，不能被反复建订阅重置。 |
| OPC UA有效通信证据 | 当前代次正常数据通知或保活均可证明通信；正常响应中携带Bad／Uncertain点值仍是通信。旧代次响应和服务错误不证明当前通信恢复。缺号／Overflow属于连续性失步，按既有C1处理，不能伪称已经证明物理网络断开。 |
| Modbus请求失败 | 本轮受影响输入不可用；整轮无任何有效协议响应才累计超时轮，连续三轮触发重连。连续10秒无有效协议响应产生通信告警。多请求轮部分成功只保全成功请求对应的输入，不使失败点恢复有效。 |
| Modbus正常协议异常响应 | 仍证明有效协议通信，相应工程值不可用；不计为整轮无响应，不冒充网络断联。库先主动关闭连接时保留CONNECTION事实。 |
| 首次启动尚无有效通信 | 输入保持未知。通信告警从实际启用采集的单调时刻计时；UA每代次订阅静默检查另从CreateSubscription成功返回开始。配置禁用的源不累计告警。 |
| 值及源时间戳保持不变，但协议通信持续 | 不判断联，继续按当前质量、源有效性和普通阈值处理；恒定越限仍可满5秒确认。 |
| 坏质量／协议无值 | 相应测点及依赖结果不可用，保留协议实际载荷和状态；不能仅凭坏质量把整个来源判断为通信断联。 |
| 浏览器连续3秒无后端消息 | 表达前后端消息中断，不算设备／网关通信断联。 |

**恢复证据：** 建连成功只表示连接建立；当前有效响应确认通信恢复，相关点取得有效输入后才恢复计算。UA在3–6秒内同代次恢复且连续性完好时，按既有同代次状态重申流程恢复；新代次仍须等待相关输入。两种恢复均不回填中断历史。

**页面文案待落实：** 已发现连接断开、但尚未达到告警阈值时，应表达“已断开／恢复中，通信告警尚未触发”，不能仅因`alarm=false`显示“通信正常”。数据失效、连续性失步也应保留各自原因，不一律称为物理断开；首次尚无响应时显示等待，不能预先显示通信正常。此处是待审核的展示要求，未声明当前页面已经符合。

## 认领结论（2026-10-20）

出处：用户2026-10-20要求把认领结论写在本文后段，并要求故障场景由“可手动配置触发的脚本”产生，而不是前端按钮、也不是按顺序自动触发。上面的表不改，保持“现状”；本节是对每一行的认领口径。**这不是“完整模拟场景已验收”：没有任何一行被写成“模拟层已验收”，模拟层只认领下表标“模拟层认领”的行，且尚未做过正式完整模拟。**

### 手动触发：脚本，不做前端按钮

`scripts/trigger_scenario.py`（用法见[模拟现场使用说明](HTSG_V1_模拟现场使用说明_v0.1.md)第5节）：在 `.local/research/trigger.json` 里写 `{"scenario": "thermal_step"}`，运行脚本，触发**一个**场景；要换场景就改文件再运行，没有顺序、没有定时。`--list` 列出场景名与持续时间。控制令牌从 `.local/research/simulation-secret.txt` 读取，不打印。

不做前端按钮的原因（评估2026-10-20）：
- 终版第15节把第7页定为“沿用管理入口，按本期 admin／viewer 权限及真实管理审计展示”，权限表写明“不允许在线修改配置”；加按钮是改冻结的设计要求，要先回写设计。
- 后端要多一条写路径：网页后端代模拟器转发控制请求，持有模拟控制令牌——被测系统与独立模拟现场耦合，生产代码里多出只在开发模式有用的分支。
- 候选摘要里的代码（`web.py`）和页面（`app.js`）都会变，已完成的整套连续运行与 G3 证据（绑定 `c761572`）作废，要重跑约50分钟。
- 取消时同样要回写设计、改代码与页面、重跑 G2／G3，成本与加入时相当。脚本在 `scripts/` 里，不在候选摘要内，加或删都不影响已有证据。

### 逐行结论

口径：**模拟层认领**＝可用上表的场景在实验前端上手动验证；**夹具层认领**＝由真实协议服务器夹具上的用例作为证据，模拟层不做；**单元层接受**＝只有单元用例，模拟层不做，风险见说明；**不认领**。
