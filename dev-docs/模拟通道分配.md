# 模拟通道分配（2026-10-08）

按用户要求，默认模拟运行满 200 个 OPC UA 订阅点，用于业主上限联调。订阅点指 monitored item/NodeId，不是建立 200 条连接或 200 个 Subscription 对象。点表位于 `config/research-sim.json`，均为部署配置，普通用户不在线增删改。

## 1 计数口径

| 类别 | 数量 | ID / 含义 |
| --- | ---: | --- |
| Modbus 原始输入 | 8 | bridge_mvv_01…08，单位 mV/V |
| OPC UA 内壁温度 | 96 | temp_inner_01…96 |
| OPC UA 外壁温度 | 96 | temp_outer_01…96，与内壁逐号配对 |
| OPC UA 过程量 | 8 | 下表所列过程量 |
| 原始输入合计 | **208** | 8 Modbus＋200 OPC UA |

| 内外壁温差 | 96 | delta_t_01…96，内壁温度−外壁温度，°C 温差 |

| 热应力代理绝对峰值（保留符号） | 1 | thermal_stress_peak，对 96 路估算结果取绝对值最大者并保留符号；绝对值相同取通道顺序在前者（修复轮15） |

96 对壁温分布在原型的 8 个模拟段 H1…H8（模拟对象为水冷壁受热管段：管外烟气加热，外壁高于内壁；修复轮15），每段 12 对。编号 i 的段号为 `(i−1)%8+1`，组号为 `floor((i−1)/8)+1`；例如 01、09、17…89 属于 H1。每段第一对与当前 8 个应变展示位置对应，其余温度组可在通信页和历史页选择。这是填满容量的模拟配额，不声称现场确有这些位置或配对。

## 2 对照原型第 1、2、4 页

依据为 `htsg_hmi.html` 中 P1/P2/P4 及 renderP1/renderP2/renderP4 的实际字段；原型的 16 路应变和 50 Hz 文案由用户规定的 8 路、1 Hz 覆盖。

| OPC UA 过程点 | 工程量 | 模拟基线（参考工况 600 MW 下的值，随负荷联动见修复轮15） | 默认极值范围 | 原型用途 |
| --- | --- | --- | --- | --- |
| load_mw | 机组负荷 | 600 MW | -20～800 MW | P1/P2 过程量、P4 负荷关系 |
| waterwall_flow | 水冷壁工质流量 | 1850 t/h | -50～3000 t/h | P1/P2 过程量 |
| main_steam_flow | 过热蒸汽流量 | 2117 t/h | -50～3000 t/h | P1/P2 过程量 |
| main_steam_pressure | 主蒸汽压力 | 28.7 MPa | -0.1～40 MPa | P1/P2 过程量 |
| feedwater_temperature | 给水温度 | 309 °C | -20～400 °C | P1 过程量 |
| reheat_temperature | 再热蒸汽温度 | 623 °C | -50～800 °C | P1 过程量 |
| working_fluid_temperature | 工质温度 | 435 °C | -50～800 °C | P4 瞬态分析输入 |
| furnace_pressure | 炉膛负压 | -0.05 kPa | -5～5 kPa | P1 过程量 |

金属壁温由温度点提供，温差由后端计算，不再额外订阅一个同名温差来重复占额。原有 main_steam_temperature、feedwater_flow、oxygen 不再进入这套按 P1/P2/P4 分配的默认点表；已有数据库记录不删除。

应变变化量只表达相邻有效结果的增量，不是变化率、异常变动识别或疲劳指标；不除以时间间隔。首次启动、跳拍、失败轮、断连或重启、前值无效或极端时返回不可用，不用 0 或旧值补造增量。峰值要求全部对应估算可用，不把缺失结果当作 0。

当前轻量范围只采用已确认的电桥换算、温差、应变增量、现有热应力代理和绝对峰值。原型中的裂纹、蠕变、法兰/汽机诊断、FE 对照，以及未确认的总/机械应力分解和许用/屈服比不因点数扩容而自动加入，也不创建待实现的占位通道。页面上的热应力峰值明确标为研究估算，不冒充原型的真实总应力峰值。

## 3 配置与验证边界

- Modbus 上限仍为 8，OPC UA 上限仍为 200；计算配置的派生项容量由 128 调整为 256，以容纳本次实际需要的 209 项。
- Modbus计划轮询及OPC UA请求采样/发布周期为1秒，通知按变化接收；批次计算、推送与完整组归档以终版为准。
- 417个可查询量不是每秒417行原始采样；按实收及变化归档，不复制静止值。开发预算10 GiB，一年容量按终版实测验收。
- 验证默认配置节点与信号一一对应、满 200 个 NodeId 接收、8 路 Modbus 同时接收、派生计数、正常场景极值以及应变增量的符号/断续语义。

2026-10-08 验证结果：完整 pytest 202 项通过、0 跳过，耗时 124.40 秒。实际双协议满量测试收齐全部 208 个输入且每点至少收到两次更新，OPC UA 服务器实际建立 200 个模拟节点。该测试证明当前默认点表可以接入，不代替长期满量归档和现场验收。
