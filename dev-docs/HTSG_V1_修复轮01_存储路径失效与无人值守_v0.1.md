## 2. 改动

- **`htsg/archive_router.py`（候选摘要随之改变）：**
  - 第1条：主库存储路径读不到时，本组返回 FAILED（`PRIMARY_DISK_UNAVAILABLE`），由提交队列按原组原 ID 重试，不猜测、不写到别处；应急库读不到只在需要走应急库时返回 FAILED（`EMERGENCY_DISK_UNAVAILABLE`），主库有空间时照常写主库。`health` 标 `primary_disk`／`emergency_disk` = `UNAVAILABLE`，读回后清除；自检页“最近错误”显示原因。
  - 第2条：回退时先写路由状态，写成功才切换；应急库连不上则本组 FAILED 等待。
  - 持续写不进时提交队列满，按既有路径记归档缺口，进程不退出。
- **`scripts/deploy_databases.py`（新增，不在候选摘要内）：** 现场只给盘符（或某盘上的绝对目录）。每个角色一个 PostgreSQL 18 实例，放在 `<盘>\HTSG\<角色>\pgdata`，同一目录写进配置的存储路径；三个角色必须在不同卷。`plan` 只检查；`install` 建目录、实例、库与表，写连接文件和配置（改前留 `.bak`）；`register`（管理员）把实例注册为自动启动、意外停止一分钟后重启的服务，并注册任务 `HTSG-Backend`；`status` 查看。不删除任何东西，重复运行只补缺的部分。
- **`scripts/supervise.py`（新增）：** 由任务 `HTSG-Backend` 以 SYSTEM 身份在开机时、并每5分钟运行一次（已在运行就不重复；用电池时照常运行；优先级4；无运行时限）。把没在运行的库服务拉起来（之后每分钟一次，移动盘晚插上也会被拉起）；等主库能连上再启动后端（最多3分钟）；后端无论因何结束都再启动，连续很快结束时间隔5秒加倍到60秒，运行满10分钟后复位；已有后端占着部署时只等待。`.local/STOP` 存在时以正常方式停止后端并退出、不再启动，删掉后5分钟内恢复。日志 `.local/supervisor.log`（有上限）。
- **`scripts/register_task.ps1` → `scripts/history/register_task.ps1`：** 被 `register` 取代，文件头已标注为历史脚本、只用于回滚（使用前须移回 `scripts/`）。README 的引用已改为指向新脚本。
