## 当前目标与实施顺序

1. 固定匿名通道与单位，评估并实现 8 路 Modbus及暂规划 200 路 OPC UA 订阅模拟；确认一秒均值的产生位置。
2. 实现全量原始历史和 5 秒故障点；保留预算、缺口与部分可用查询。
3. 按已确认的 GF=6、N=1 和 x × 1000 / 6 实现微应变换算，继续核对机械应变的物理解释；适配第二页和第四页，提供任意中心窗口回溯入口。
4. 执行新机制验证，记录环境、规模、时长、错误与缺口。旧 35 分钟 Pre/Post 验证不能作为新故障机制验收。

## 验收意图

- 固定值协议验证：mV/V 原始值保持，OPC UA 浮点不换算；订阅通知实际走采集链路，不由浏览器生成业务值。
- 全量历史：正常期和故障期每个启用通道均可查询原始记录；换算值不覆盖原始值，缺失不伪造。
- 故障确认：不足 5 秒并复归不记故障；持续 5 秒记录确认点；持续未复归不重复记同一故障，复归后下一次可记录。无效/缺失等边界待决定后补验收。
- 窗口历史全局重现：用故障点定位后，可调整中心时刻、窗口长度及查看通道；同一窗口可查看未发生故障的已保存通道，扩大窗口可读到旧事件区间外的已保存记录；也可不选择故障点直接定位。缺口和部分库失败可见；验证跨页读取及允许的自动填充。

## 故障与历史模块修正清单（已改写，待用户审核）

| 项目 | 原实现 | 本轮目标 |
| --- | --- | --- |
| 故障确认 | 首次越限立即触发事件 | 持续满 5 秒，记录确认点的通道、数值和时间 |
| 记录粒度 | Profile 汇集多个触发通道与事件阶段 | 按通道记录确认点；同一轮持续异常不重复记录，复归后重置 |
| 历史入口 | 按事件与关联数据进行故障历史查询 | 替换为以故障点为参考的客制化窗口历史全局重现 |
| 时间范围 | 固定 Pre/恢复/Post 捕获区间 | 用户指定中心时刻和窗口长度，中心前后各半窗 |
| 通道范围 | 事件 Profile 关联名单 | 全量历史中同一窗口内已保存的通道均可查看 |
| 数据来源 | 事件捕获的原始样本及关联帧 | 独立于故障的持续原始归档与实际保存的计算结果 |
| 旧数据 | 按旧事件结构解释 | 保留既有记录及解释；未保存的历史区间显示缺口 |

本表所列故障与窗口重现已写入源码。故障边界采用本文件现行规定中的本轮实现约定，供用户审核；相邻观测最多 1.5 秒是 1 Hz 下的抖动容许值，超出即重新计时。确认使用满 5 秒后的首个有效越限观测，保留其实际时间和值，不插值构造恰好第五秒的数据。

2026-10-06 验证：完整 pytest 套件 181 项通过，0 跳过，耗时 107.82 秒；包括真实双 PostgreSQL 实例的独立测试库、正常/故障/复归原始归档、故障去重、跨通道窗口、进程中断、协议断连恢复及 Chrome 交互。ruff、JavaScript 语法检查、研究配置校验与 git diff --check 均通过。两条告警为既有测试客户端依赖弃用提示。此前未运行的备用开发实例已启动以完成测试；测试库由夹具删除。现场持续吞吐与长期容量未由这些测试证明。

独立历史查询页（5）位于热应力分析（4）与系统自检（12）之间。故障列表可定位中心时间和参考通道，用户可改中心时间、窗口秒数和任意已配置通道；离页再返回保留查询条件和故障参考。总览、应变场、热应力页不再嵌入自定义历史查询，热应力页保留最近 5 分钟分析曲线。前端每次最多展示 10000 条并提示缩窗，接口通过游标分页。输入时间按浏览器本地时区解释，接口统一为 UTC Unix 秒，范围为 `[center-seconds/2, center+seconds/2)`。
- 公式与界面：以 6 mV/V → 1000 με、-6 mV/V → -1000 με、0 → 0 核对公式，防止重复激励归一化或倍率错误；图型与云图语义明确后检查展示和数据一致，不用曲线外观证明算法正确。
- 资源与权限：评估通道规模、增长、重启、订阅恢复、预算拒写及 admin/viewer，开发库仅 D 盘，不填满实盘。
