## 1. 执行规则

- 按D01—D48顺序执行；表中依赖是最低依赖，不是允许跳过前置capstone。P0为核心正确性，P1为查询展示，P2为候选接线、测量与交付；优先级不替代依赖顺序，三类都必须完成。本次通信页修订按第12节D44a—D44f顺序实施，继承受影响模块的capstone及H0要求，不要求重复已完成的开发任务。
- 每项目标约100行有效业务代码，表中给出合理区间；SQL计入，测试、生成点表和纯删除另计。行数是拆分估计，不是配额。超过200行时按输入/输出边界继续拆子项并继承原验收，不能拆散事务来凑行数。
- 每项完成记录：改动文件、用例、实际命令、通过/失败/跳过数及遗留问题。新增记录或接口必须同时更新直接调用方。测试验证业务不变量，不只验证硬编码输出。
- 使用隔离开发分支和新测试库；不对旧开发/研究库迁移或删库。D45只在隔离环境统一候选版本接线；D46、D47及切换前检查点H0通过后，才在D48切换运行入口；不建立长期双架构开关或兼容层。
- 每个capstone必须在同一代码版本重跑模块集成用例。失败则留在该检查点，不把后续通过结果当作补偿。现场未验证项必须在交付记录中单列。
- 本期不新增跨源同步、Republish、重模型、死点/跳变检测、空间插值或旧历史迁移。
