# HTSG 0.2.0 科研模拟现场

本轮实现原型界面编号 1、2、4、12、14、15。模拟器提供真实 Modbus TCP 和 OPC UA 服务，后端主动读取并计算、归档，浏览器读取后端接口。默认 660 MW 只是已确认方案中的演示参数，不代表获得了现场机组参数。测点位置、内外温度配对、材料参数与报警阈值均是科研假设。

## 启动

在项目根目录 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe scripts\bootstrap_db.py start
.\.venv\Scripts\python.exe scripts\research_lab.py run
```

打开 `http://127.0.0.1:8000`。登录凭证从本机 `.local/research/initial-credentials.json` 复制，对应 `admin` 和 `viewer`。凭证不放入 URL，不提交该文件。`Ctrl+C` 结束本次演示。默认端口：Modbus 15020、OPC UA 14840、模拟控制 14841、网页 8000。网页、数据库客户端和模拟现场都仅使用本机回环连接。

启动脚本在 D 盘已有的两个开发 PostgreSQL 实例中创建独立、随机名称的实验数据库，并保存连接信息到 `.local/research/database.json`；再次启动复用该实验库。它会检查实际数据库目录仍在 D 盘及实验库名称，等待模拟服务配置匹配后才启动后端。C 盘不部署数据库。脚本不删除旧历史；超过开发预算时会明确停写并显示故障，不能把重新启动当作无限压测的方法。

默认开发写入/占用上限为 10 GiB，同时检查本进程累计序列化写入量及两实验库用户表与索引总量；总量包含以前的试验，不是每次启动都归零的增量。该上限不包含 WAL、系统目录等全部磁盘空间，另有 D 盘至少 1 GiB 剩余空间保护。启动估算也不包含既有数据和 WAL，不能代替运行中实测。

后台若仍在运行，再次启动会拒绝占用的端口或部署锁。不要手工覆盖 `.local/research` 内的数据库信息来连接现有业务库。

## 修改模拟设定

统一入口为 `config/research-sim.json`。修改后执行下面的校验，再停止并重新启动演示：

```powershell
.\.venv\Scripts\python.exe -m htsg.cli check --config config\research-sim.json
```

| 配置位置 | 可修改内容 |
| --- | --- |
| `project` | 标题、额定容量、科研说明 |
| `simulation.signals` | 各点基值、波幅、周期、噪声、相位；随机种子固定，时间按真实时钟推进 |
| `simulation.scenarios` | 异常涉及测点、增量、持续时间、断连或坏质量场景 |
| `sources / points` | 本机端口、寄存器、数据类型/字节序、NodeId、单位、缩放、采样间隔和阈值 |
| `models / derived` | E、热膨胀系数、约束系数、敏感性范围、依据、模型版本及输入映射 |
| `profiles` | 壁温越限时记录哪些相关点与曲线；时长当前固定 600/60/1200 秒 |
| `ui` | 测点示意坐标、中文标签、展示精度、过程量、历史时间窗 |
| `limits / storage` | 队列、捕获与写入预算；空间阈值只在专门的隔离测试中模拟，不填满磁盘 |

默认 8 组应变/内外温度点与 7 个过程量，共 31 路源输入；另有 8 路温差与 8 路热应力估算。默认追忆仅关联 S01 的应变、内外温度、机组负荷及其温差/应力曲线。这是可修改的关联配置，并非自动推断拓扑。其他测点仍显示和归档常态历史。

## 页面与实验

- 总览：观察数值、质量、历史与事件；选择事件查看关联数据及缺口。
- 测点示意：切换应变、温度或应力估算，选择示意位置查看该点趋势；位置不代表实际拓扑。
- 热应力：同时查看应力、温差、负荷历史及公式参数。输出是带符号的温差代理量；正负不等于真实拉压应力。
- 系统自检：查看连接、采样、队列、归档与数据库状态。没有输入支持的硬件诊断不显示为通过。
- 通信日志：查看协议读数和映射、实际错误与恢复记录。日志是最近 500 条运行内存记录，重启后重新开始。
- 系统管理：只读用户查看数据，管理员管理账户和模拟场景。阈值/模型更改在配置文件中进行，重启生效。

例如在总览页选择“壁温突升”，模拟器会使 S01 内外温度和应变发生设定变化，后端读取越限值后建立事件，保留触发前 10 分钟；温度恢复正常并连续确认 1 分钟后，再记录 20 分钟。应先运行至少 10 分钟再触发，否则 Pre 不足会被如实标记。模拟场景控制只改变模拟服务器，不向真实设备写值。

`OBSERVED` 表示保留观测能以边界样本，或间隔不超过 `stale_after` 的相邻观测，证明 Pre 左边界，且没有记录到重叠丢失；它不保证所有样本都为 GOOD，也不代表物理信号连续。冻结场景保留值与 OPC UA 源时间戳；在接收时间模式下，成功读回的恒定值不能单独证明设备故障。

## 验证与交付边界

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\validate_ui.py
.\.venv\Scripts\python.exe scripts\validate_research_cycle.py
```

后两个命令需要演示服务已经启动；浏览器脚本需要 `.venv` 中的 Playwright 和本机 Chrome。完整周期脚本默认观察 2100 秒，先预热 605 秒再触发一次异常，输出 `docs/research-cycle-result.json`。验证期间不要切换场景或重启服务。浏览器脚本的 `--scenario-controls` 选项会切换基线，只能在完整周期之外执行。

浏览器测试工具通过 `.\.venv\Scripts\python.exe -m pip install -r requirements-validation.lock` 安装；运行网页本身不需要 Playwright，也不需要访问 CDN。

账户管理以数据库为权威来源，数据库账户变化与管理记录同事务提交。若提交结果不明或本地账户文件更新失败，`.local/research/accounts.pending` 会保留未决标记，凭证验证及已有实时连接暂停；数据库恢复后重启后端，由数据库状态协调本地缓存。不要手工删除标记来绕过协调。管理记录的 `COMMITTED` 表示数据库事务完成；不等于本地文件发布完成。无未决标记而数据库暂不可用时，保留原来的本地鉴权缓存能力。

模拟器源账本有界保存最近 120 次更新，供验证协议解码与源时间戳；业务接口没有直接注入这批数据。热应力验证采用独立算式核对，不能据此宣称真实机组模型精度已经验证。真实工程映射、材料/测量依据、长期容量、系统盘紧急实例及现场跨盘行为仍按原遗留项处理。

## 实验库预算耗尽后开始新一轮实验

实验数据库的 10 GiB 开发预算包括此前实验遗留的数据。停止再启动会复用同一数据库，因此不会恢复已经耗尽的预算。`prepare` 和 `run` 启动前会测量两库用户表与索引总量，显示剩余预算；不足一次完整追忆周期的估算量时会醒目提示，已满时仍可启动查看已有历史，但不能继续归档新的追忆。估算不是容量保证，也不包含 WAL 等全部磁盘开销。

需要重新实验时，先在运行窗口按 `Ctrl+C` 正常停止服务，再执行：

```powershell
.\.venv\Scripts\python.exe scripts\research_lab.py new-lab
.\.venv\Scripts\python.exe scripts\research_lab.py run
```

`new-lab` 在 D 盘既有两实例内创建新的随机名实验数据库，并把旧连接文件保存在 `.local/research/archives/<唯一编号>/database.json`。旧数据库及历史保留，账号、登录凭证和模拟控制密钥继续复用；当前页面此后查询的是新库，不会把旧库历史合并到新实验。命令与后端使用同一部署锁，服务运行时会拒绝切库。存在账号提交未决标记时，必须先在原库完成协调，不能用换库跳过。

此命令不提高写入预算，不删除或自动轮换旧库。多次创建的新旧实验库仍共同占用 D 盘空间；磁盘剩余空间保护继续生效。请按实验需要显式创建，不将其作为长期运行的自动扩容方式。
