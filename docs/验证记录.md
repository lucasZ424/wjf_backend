## 现行开发规定（2026-10-06）

用户已裁定所有机制冲突以《遗留问题.docx》为准；Bridge 单位和公式采用用户于 2026-10-06 的补充确认。本节替代旧设计要求；文件名中的原版本号保留用于引用，不代表正文仍采用旧规则。

- 科研监测；Windows 原生单机、PostgreSQL、admin/viewer；配置校验后重启，不增加热切换或现场控制。
- Modbus 从 Acheron 读取 8 路 Bridge，返回值已为 mV/V；使用一秒均值。GF 暂统一为 6，全桥配置因子 N=1；换算公式为 `ε[με] = x[mV/V] × N × 1000 / GF = x × 1000 / 6`。原始 mV/V 与换算微应变分别表达，原始值不被换算结果覆盖，不再除以激励电压。温度补偿及能否直接称为机械应变仍待确认；GF=6 是当前统一规定，不代表逐传感器标定已完成。
- OPC UA 采用订阅，容量上限固定为 200 路工程量；现场实际订阅点由部署配置确定，经校验后重启生效，不向普通用户提供运行时新增、删除或修改通道。浮点值无需换算；具体订阅信息现场确认，当前模拟占位。协议级单订阅 200 通道已通过本地模拟验证，现场服务器限制与持续吞吐仍需联调。
- 两路输入与后端统一 1 Hz，按后端接收时间对齐。真实工程量、通道编号和阈值待定；模拟工程量参考前端原型，临时阈值须注明依据和模拟性质。
- 所有原始数据长期保存；不再仅在事件区间保存源样本。换算机械应变的保存要求、长期的具体期限及容量方案待明确，不沿用旧 30 天种子或事件样本一年规则替代全量长期要求。
- 越限持续 5 秒不复归时，记录第五秒的单点值、故障通道与时间戳；复归后重置监测。替代即时事件捕获和固定 600/60/1200 秒 Pre/恢复/Post 机制；即时提示是否保留未定义。
- 原故障历史查询替换为以故障点为参考的客制化窗口历史全局重现：故障点提供参考时间和通道，用户可调整中心时间、窗口长度及查看通道；从全量长期历史读取中心前后各半个窗口的数据，可查看同一窗口内其他已保存通道，不受旧事件关联名单、故障通道或固定捕获区间限制。也允许手动选通道与时间，无需先有故障记录。故障点列表承担定位入口；独立“历史查询”页位于热应力分析之后、系统自检之前，集中提供故障定位、参考通道与中心时间自动填充及窗口调整；总览、应变场和热应力页不再嵌入自定义历史查询。
- 本次不判断跳变、死点。协议坏质量、断联、过期与缺失不视作正常有效数值；它们对故障确认及复归的影响按本轮实现约定执行，供用户审核。
- 前端沿用原型页 1、2、4、12、14、15，并在热应力分析（4）与系统自检（12）之间增加独立历史查询页（5），共七页；第二页计算机械应变，云图暂时保留，其插值/示意定义待定；第四页合并负荷、应力、内外温差关系为一个图，图型、单位和合理性待评估。
- 保留不冲突的 10 GiB 开发预算、开发库仅 D 盘、暂停自动清理、95% 移动盘接续与余量保护。本轮最终应急接收连续原始观测及故障点，帧与派生结果暂停归档并报告缺口；不承诺预算或磁盘耗尽后无损。

当前源码已改写协议接入、微应变换算、按通道持续满 5 秒故障确认、持续原始归档和客制化窗口历史重现；默认配置已移除 Pre/Post 捕获。旧事件表和读取接口保留用于既有历史。以下故障边界为本轮实现约定，供用户审核：严格 > 上限或 < 下限；正常值、坏质量、断联、乱序或相邻观测间隔超过 1.5 秒打断待确认计时，方向切换重新计时；确认后仅有效正常值复归；重启重新计时，既有记录保留，持续异常可能在重启后再次确认。现场阈值、长期容量和其余图型尚未验收，旧验证材料只代表当时实现。

种子覆盖采用实际独立帧计数；稀疏记录之间的时间跨度不能冒充覆盖秒数。归档恢复不会用一个新时间戳释放整段旧种子。健康接口提供逐点种子覆盖/有效覆盖、首末窗口和测量时间，以及最后成功帧归档时间、距今秒数和紧急停写标志。统计是周期快照，数据库不可读时不能视作实时可信测量。

## 已覆盖的关键行为

- 即时异常先于均值；同秒 HIGH/LOW；样本预算溢出仍保留方向事实；极端有限输入的算术溢出不停止引擎；六种聚合、保持/失效、迟到不解除当前异常。
- 连续恢复被真实失效打断、同时间歧义不证明恢复、Post 复触发、关闭后的末帧和资源中断。
- 时间回拨产生独立运行段；旧计算不能关联新段事件或覆盖最新展示。
- 派生计算缺输入/超时返回不可用；多层算子传递保持年龄；变化率拒绝过期的前帧；未配置热应力不输出数值。
- PostgreSQL 真实事务、重复记录幂等、停写和稀疏恢复的种子保护、按首次归档时间的一年原始样本保护、结果清理与查询标记。
- 注入 95%/70% 水位验证切入/切回、路由重启恢复、备用保留线拒绝、紧急实例只存源样本和必要元数据、首批样本与事件信息同事务。
- 两实例查询去重、较新事件版本优先、旧副本缺口不丢失、部分实例不可用明确返回；事件历史只暴露 Profile 指定测点。
- 数据库慢写不阻塞异常判定；入队超限可见；数据库重连不误关闭正在采集的事件。
- 本机真实 TCP 的 Modbus 与 OPC UA 服务端集成测试，包含格式解码、读取值、质量及时间戳；未连接现场设备。
- HTTP 权限、最后管理员保护、账户持久化失败不激活新凭证、WebSocket 首次认证/快照/触发通知、慢订阅者合并与重同步。

开发容量保护采用 128 MiB 业务预算、增长预估和至少 1 GiB 可用余量；测试不制造填盘文件、不在 C 盘启动备用库。应用预检查不构成 WAL 或其他进程的物理磁盘配额。

## 2026-09-21：真实工程输入前的故障验证补齐

用户确认验证思路后，新增 `tests/test_fault_validation.py` 的 **11 项故障测试**，进程退出辅助程序为 `tests/fault_capture_worker.py`。当前完整套件 **80 passed、0 failed、0 skipped，49.54 秒**，原始 JUnit 为 `.local/fault-full.xml`。两条既有依赖弃用警告仍存在。

| 验证 | 实际方法与结果 |
| --- | --- |
| 提交结果未知（2 项） | 分别在真实提交前、真实提交后向 writer 注入 OperationalError；检查 writer 确实重试相同记录。提交后分支还写入较新事件版本。样本/帧关联无重复，较新版本不倒退，种子计数仍为 1，无归档丢弃。未模拟底层网络协议丢包或物理断电。 |
| 断连恢复（1 项） | pg_terminate_backend 只终止随机测试库的指定写连接。实际写任务报错、重新连接并归档，状态判定继续，核心任务未退出。 |
| 捕获进程强制退出（3 项） | 分别在 Pre 作业尚待完成、Active、Post 时终止本测试创建的 Engine/Store 子进程，并留下一条未提交记录。重启执行正式 Router 核对路径：已提交样本保留、未提交记录不存在、旧事件 INTERRUPTED/PARTIAL，新 Engine 使用独立运行段。本项不等同于完整 Windows 服务重启或操作系统断电。 |
| 写入背压（1 项） | 用线程闸门阻塞真实写入，限制入口/事件/普通队列为 16/16/4，持续提交 900 次观测。队列保持有界，入口与归档溢出可见，存在事件关联缺口；释放闸门后恢复写入。 |
| 在途捕获预算（1 项） | 提交多个捕获作业，共享 4096 字节小额预算；预算内接纳，超出明确拒绝。已接纳作业真实归档后释放全部预算。它验证显式预算记账，不是操作系统进程总内存峰值测量。 |
| 计算停滞（1 项） | 阻塞计算线程并推进虚拟帧，计算队列不超过 4；溢出帧返回 CALCULATION_QUEUE_FULL，仍能判定并通知 HIGH，释放后计算可继续交接。 |
| 清理锁等待（1 项） | 在测试库实际持有排他表锁，使维护真实超时；释放锁后维护恢复 OK，受保护种子未删除。 |
| 升级失败（1 项） | 在初始化 DDL 末尾追加测试建表与除零错误，事务失败后测试表不存在、已有历史仍在；去除故障后初始化成功。旧结构顺序回填由既有升级用例共同覆盖。 |

首轮断连测试曾因“任一写任务成功”后立即查询事件而失败；空 Pre 作业可先于事件事务完成。测试已改为有截止时间地等待实际事件落库，未把健康时间戳当作全部归档完成的确认。本轮没有发现需要修改业务代码的新缺陷，交付运行版本仍为 0.1.1，既有 wheel 不变。

Ruff lint 全部通过，新增文件格式检查通过。全仓格式检查另外发现 `runtime.py`、`test_audit_regressions.py` 有既有混合换行，未在本次验证任务中改动；不将全仓格式检查报告为通过。
