# HTSG 模拟数据源 使用说明

本包在**已经按发布包装好**的电脑上，起一个独立的模拟现场（Modbus 与 OPC UA 服务，按模拟通道分配发出数据），供没有现场设备时演示和测试，并可手动触发一个异常场景。它只发数据，不写任何真实设备，也不改后端程序或数据库。版本与构建来源见 `VERSION.json`；须与发布包版本相同。

## 1. 核对与放置

在本包目录里打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1
```

显示“校验通过”后，把包里的 `sim` 文件夹整个拷到程序目录（如 `D:\HTSG\app\sim`），与 `.venv` 并列。

## 2. 让后端连模拟现场

模拟现场只监听本机回环地址，后端须在同一台电脑上。安装与运维说明第3节“生成配置（点表）”这一步改为直接用本包的配置：

```powershell
Copy-Item sim\production.json config\production.json
.\.venv\Scripts\python.exe -m htsg.cli check --config config\production.json
```

它是正式模式：点表与数据源地址指向本机模拟服务，项目名称、存储路径等与发布包的生产基础配置相同，页面不显示“模拟数据”字样。其余部署步骤（第4节起）照常。

## 3. 启动模拟现场

在程序目录里另开一个 PowerShell 窗口（这个窗口要一直开着，关掉即停止）：

```powershell
.\.venv\Scripts\python.exe sim\sim.py start
```

第一次启动时生成控制令牌，存在 `sim\.local\simulation-secret.txt`（不打印，不要外传）。模拟现场先起、后端先起都可以：后端连不上时会自己按间隔重连。`Ctrl+C` 停止模拟现场，后端随即显示断连，这本身也是一种异常演示。

## 4. 触发异常场景

```powershell
.\.venv\Scripts\python.exe sim\sim.py list               # 看有哪些场景
.\.venv\Scripts\python.exe sim\sim.py trigger freeze     # 直接按名字触发
.\.venv\Scripts\python.exe sim\sim.py trigger            # 或触发 sim\trigger.json 里写的那个
```

`sim\trigger.json` 只写一个场景名，例如 `{"scenario": "disconnect_modbus"}`，改了再运行即可。一次只触发一个场景，到时自动回到基线；再触发一个会替换正在进行的。场景及时长以 `list` 的输出为准，当前有：回到基线、温度阶跃、负荷变化、温度极端、质量变坏、数据冻结、断开 Modbus、断开 OPC UA。

## 5. 注意

- 模拟现场不随开机自动启动，也不由看守程序拉起；断电重启后要再执行第3节。
- 改回真实设备时，按安装与运维说明第3节用点表重新生成 `config\production.json`，再按第6节重启后端；`sim` 文件夹可以删掉。
