# HTSG 模拟手册

用模拟数据源包在一台电脑上搭起“模拟现场＋HTSG”，用于给客户演示和做测试；用完后用包里的清除工具把模拟安装、数据、数据库实例、服务和端口全部去掉，**不让模拟数据留在现场电脑上**。版本见 `VERSION.json`，须与发布包相同。

## 1. 包里有什么

| 入口 | 用途 |
| --- | --- |
| 1-启动模拟现场（演示） | 给人看：负荷、流量、压力、壁温、应变随负荷与局部热负荷联动，曲线变化明显（壁温约两三秒动一位，全场每秒约 85 个点有变化） |
| 1-启动模拟现场（稳态） | 做长时测试：同一个机组模型，按真实机组的节奏慢变（负荷平稳时壁温一两分钟才动 0.1 ℃，全场每秒约 3 个点有变化） |
| 2-触发场景 | 按编号选一个场景触发，复现变负荷、越限、断连等用例 |
| 3-清除模拟安装 | 去掉模拟安装产生的一切（第5节） |
| `production.json` | 让 HTSG 连模拟现场的配置，安装时交给发布包的安装程序 |
| `production-长时测试.json` | 长时测试用（第4节）：同上，只把应急预留调小到 256 MiB，两块小虚拟盘上也能走到转应急库 |

两档的物理关系、场景和越限完全相同，只是数据变化快慢不同。模拟机组按 660 MW 超超临界直流炉、600 MW 参考工况构造，测站当作水冷壁受热管段（外壁高于内壁）；数字是演示设定，不是真实机组的保证值。

## 2. 部署模拟

需要：发布包 `HTSG-…`、本包 `HTSG-SIM-…`（同一版本），一台 Windows 电脑，两块本地盘（正常库、应急库各一块；应急库所在盘至少留 100 GiB）。

1. 两个包都拷到电脑上解压，各自在包目录里运行 `powershell -ExecutionPolicy Bypass -File .\verify.ps1`，显示“校验通过”。
2. 把本包的 `production.json` 拷到发布包文件夹旁边（同一目录）。
3. 双击发布包里的“安装.cmd”，授权后按提示选两块盘，等到“安装完成”（详见发布包《安装与运维说明》第2节）。管理员初始口令在 `D:\HTSG\app\.local\initial-credentials.json`。
4. 双击本包的“1-启动模拟现场（演示）”或“（稳态）”。这个窗口要一直开着；关掉即模拟现场停止（后端会报断连，这本身也是一种异常演示）。模拟现场与后端谁先起都可以。
5. 浏览器打开 `http://127.0.0.1:8000`，用 admin 和初始口令登录；“系统自检”页两个数据源“数据有效”即连好。

模拟现场不随开机启动；电脑重启后后端与数据库自己起来，模拟现场要再双击第4步的入口。

## 3. 复现用例

双击“2-触发场景”，按编号选一个回车。一次只生效一个场景，到时自动回到基线；再触发一个会替换正在进行的。下表的“应看到”是 2026-11-01 在本机实跑（演示档）的结果。

| 场景 | 持续 | 应看到 | 复归 |
| --- | --- | --- | --- |
| 变负荷 | 20 分钟 | 负荷按 12 MW/min 降到约 510 MW、保持约 5 分钟、升回；流量、压力、给水温度、壁温、温差、热应力随之平滑变化。**不产生任何越限** | 场景结束回到基线摆动 |
| 测点01局部超温 | 10 分钟 | 约 2.5 分钟后测点01的内外壁温差“故障已确认（低）”，随后外壁温度（高）、应变（低）也确认；热应力页该温度对曲线变橙；其他测点不动。共 3 条故障记录 | 场景结束后约半分钟内全部复归 |
| 超负荷 | 20 分钟 | 负荷升到约 690 MW（**不到 693 MW 负荷高限，负荷本身不报**）；主汽流量约 2.5 分钟后、主汽压力约 6 分钟后“故障已确认（高）”；壁温不越限。共 2 条故障记录 | 降负荷途中复归 |
| 测点01温度传感器极端值 | 30 秒 | 测点01内壁温度标“极值”；它的温差、热应力不可用，热应力峰值不可用（峰值要求全部温度对有效）；不产生故障记录 | 场景结束即恢复 |
| 质量变坏 | 20 秒 | 测点01内壁温度、电桥01 标质量坏；依赖它们的量不可用 | 场景结束即恢复 |
| 数据冻结 | 20 秒 | 数据仍有效，**不误报断连** | — |
| 断开 Modbus | 20 秒 | 约 10 秒后 Modbus 数据源报断连，电桥与应变不可用；OPC UA 不受影响 | 自动重连，恢复“数据有效” |
| 断开 OPC UA | 20 秒 | 约 6 秒后 OPC UA 数据源报断连，温度、过程量不可用；Modbus 不受影响 | 自动重连 |

越限持续满 5 秒才确认。历史查询页可回看各场景期间的曲线与故障记录（回放图中数值超出限值的段画橙色）。

以下几项不靠场景，直接操作：

| 做法 | 应看到 |
| --- | --- |
| 关掉模拟现场窗口，5 分钟后再双击启动 | 两个数据源都报断连；起来后自动恢复 |
| 在 `D:\HTSG\app\.local` 下建空文件 `STOP`，等后端停下后删掉 | 后端正常停止；删掉后 5 分钟内看守程序把它再拉起，开始新的一次运行 |
| 任务管理器里结束后端的 python 进程 | 5 分钟内被拉起，上一次运行在重启时收尾 |
| 正常库所在盘到 95% | 写入目标变为“应急库”，各页有提示，采集照常 |

## 4. 长时运行测试（12 小时）

用稳态档，只看“不崩溃”（项目硬规则：一年运行不崩溃）：其间要走到写满的两条路——**超过 90% 启动滚动删除**、**到 95% 转到应急库**——并穿插第3节的异常操作。正常库和应急库**都放在两块 1 GB 的小虚拟盘上**，否则 12 小时内到不了这两条线；安装用本包的 `production-长时测试.json`（与 `production.json` 只差一项：应急预留从 100 GiB 调小到 256 MiB，否则小盘上的应急库会拒写）。

测不到的：真正删掉一个桶（保底至少要有 1 个更新的已封存桶，换桶一天一次，要约 38 小时），这一项由用例覆盖，本测试只看删除**启动**与“没有满足条件的删除范围”。

### 4.1 准备

1. 电脑设为接通电源时“从不”睡眠，暂停 Windows 更新；测试期间除下面的操作外不动电脑；**测试中途不要重启**（虚拟盘重启后不会自动挂回）。
2. **开始时间在中午 12 点到晚上 11 点之间**：换桶要“本地日期变过且当前桶累计运行满 12 小时”，这样换桶落在约第 12 小时（停机类异常操作停掉的时间不算运行时间，所以测试要比 12 小时多留半小时到一小时，看到“系统自检”页的桶号变化为止）。
3. 管理员 PowerShell 里运行 `diskpart`，建两块虚拟盘（文件放 D 盘）：

```text
create vdisk file="D:\HTSG-vhd\primary.vhdx" maximum=1024 type=expandable
attach vdisk
create partition primary
format fs=ntfs quick label=HTSGPRI
assign letter=V
create vdisk file="D:\HTSG-vhd\emergency.vhdx" maximum=1024 type=expandable
attach vdisk
create partition primary
format fs=ntfs quick label=HTSGEMG
assign letter=W
exit
```

（先建好 `D:\HTSG-vhd` 文件夹。）

### 4.2 安装与启动

1. 按第2节部署，但**不要**把 `production.json` 拷到发布包旁边：双击“安装.cmd”，提示要配置文件时把本包的 `production-长时测试.json` 拖进窗口；提示选盘时正常库填 `V`、应急库填 `W`。也可以在管理员 PowerShell、发布包目录里一次做完：`.\runtime\python.exe setup\install.py --config <本包目录>\production-长时测试.json --primary V: --emergency W:`。安装检查会提示两块盘剩余空间少（“只剩 0.9 GiB”），这是预期的。
2. 双击本包的“1-启动模拟现场（稳态）”。
3. 另开一个 PowerShell 窗口一直开着，每 5 分钟记录进程资源和两块虚拟盘的占用：

```powershell
while ($true) { $t = Get-Date -Format s; Get-Process python | Select-Object @{n='time';e={$t}},Id,@{n='MB';e={[int]($_.WorkingSet64/1MB)}},HandleCount,@{n='Threads';e={$_.Threads.Count}} | Export-Csv D:\proc.csv -Append -NoTypeInformation; Get-Volume -DriveLetter V,W | Select-Object @{n='time';e={$t}},DriveLetter,@{n='UsedMB';e={[int](($_.Size-$_.SizeRemaining)/1MB)}},@{n='SizeMB';e={[int]($_.Size/1MB)}} | Export-Csv D:\disk.csv -Append -NoTypeInformation; Start-Sleep 300 }
```

### 4.3 用占位文件把正常库推到两条线

稳态档写入很少，正常库自己涨到 90% 要很久，用占位文件把 V 盘顶上去（占位文件可以随时删掉或换大小，不用重装）：

1. **第 1 小时末**：从 `D:\disk.csv` 看 V 盘这一小时涨了多少（记为每小时 G MB）和现在已用多少（U MB）、总量（S MB）。建第一个占位文件，让约 2 小时后到 90%：大小 = 0.90 × S − U − 2 × G（单位 MB）。在 PowerShell 里：`fsutil file createnew V:\filler1.bin <大小MB×1048576>`。
2. **约第 3 小时，V 盘过 90%**，应看到：
   - “系统管理与权限”页的管理操作记录出现“开始滚动删除”（操作者“系统”）；
   - 过 10 分钟，“系统自检”页出现“主库超水位报警：占用持续高于删除启动线 …… 原因：没有满足条件的删除范围”（保底桶数不够，删不了桶，这正是 12 小时内的预期）；
   - 采集、页面、历史照常。
3. **看到报警后**：再建第二个占位文件，让约 1 小时后到 95%：大小 = 0.95 × S − 当前已用 − G。
4. **V 盘到 95%**，应看到：“系统自检”页写入目标变为“应急库”，各页有提示；W 盘开始增长；历史查询页新数据照常可查；采集不断。
5. **可选（测试快结束时）**：删掉两个占位文件，V 盘降到 90% 以下，写入目标应切回“正常库”。

### 4.4 其间的异常操作

前 8 小时内穿插第3节的场景与直接操作（断开 Modbus／OPC UA、冻结、质量变坏、极端值、关模拟现场窗口 5 分钟、STOP 停机再恢复、任务管理器结束后端进程），逐项记下实际表现。转到应急库之后至少再做一次断开 OPC UA 与一次 STOP 停机恢复，看应急状态下也能正常停下、拉起、续写。

### 4.5 结束与结果

1. 看到换桶（“系统自检”页桶号变化）后结束。
2. 整理：每项异常的实际表现；`D:\proc.csv` 里内存、句柄、线程是否只涨不落；`D:\disk.csv` 里两块盘的占用曲线；过 90%、报警、转应急、换桶的时刻；`D:\HTSG\app\.local\backend.log` 与 `supervisor.log` 里的错误。
3. 按第5节清除，再在 diskpart 里卸下并删掉两块虚拟盘：`select vdisk file="D:\HTSG-vhd\primary.vhdx"` → `detach vdisk`，emergency 同样，最后删 `D:\HTSG-vhd`。

## 5. 清除模拟安装

演示或测试结束、离开现场电脑之前，**必须清除**：

1. 关掉模拟现场窗口（不关也行，清除工具会停掉它）。
2. 双击本包的 **“3-清除模拟安装”**，授权。它先列出要清除的每一项，输入“清除”回车才动手。
3. 它依次：放 STOP 让后端正常停下 → 删开机任务 HTSG-Backend → 停止并删除两个数据库服务 → 删两块盘上的数据目录（`<盘>\HTSG\primary`、`emergency`，含数据库实例与全部模拟数据）→ 删程序目录 `D:\HTSG\app`、数据库软件 `D:\HTSG\pgsql`、安装日志 → 停模拟现场、删它的控制令牌。最后逐项核对：端口 8000、55440、55441、14840、14841、15020 都不再监听，服务、任务、目录都不在，才显示“清除完成”。
4. 手动删掉两个包的文件夹（清除工具正在运行，删不了自己所在的包）。做过长时测试的，再按第4.5节卸下并删掉两块虚拟盘。

安全与可靠：

- 它**只清除模拟安装**：已安装配置的数据源与本包 `production.json` 不一致（即真实现场的配置）时拒绝，什么都不动。
- 数据目录里有本程序以外的文件时不删那一个目录，列出来请人工查看。
- 中途出错或断电，再双击一次即可：动手前清单已存在本包 `sim\.local\cleanup-plan.json`，程序目录没了也能照它接着清。
- 只想先看会删什么：`.\runtime\python.exe sim\cleanup.py --dry-run`。装在别的根目录时加 `--root E:\HTSG`。

## 6. 常见问题

- **页面上曲线是红色一段段的**：浏览器标签页切到后台很久，浏览器降低了页面读取频率，期间页面没有读到数据，画成“无数据”；切回前台后正常。后端数据本身是连续的，历史查询页可以看到。
- **触发场景提示连不上模拟现场**：模拟现场窗口没开或已关，先双击“1-启动模拟现场”。
- **超负荷时负荷没报警**：负荷高限是 693 MW，场景只升到 690 MW，设计如此；报警的是主汽压力与主汽流量。
